## Architecture gate

- Implement game/server authority, identity, persistence, care/growth, AFK jobs, training, competitions and rewards in the existing Rust service/crates. Use agreed Rust/WASM boundaries for shared browser mechanics. Client/platform adapters belong in the client repository and consume that real protocol.
- `apps/api` does not migrate or integrate the canonical Rust JSON profiles, owner/gear/Tiny receipts, resident routines or the isolated Rust accounts workstream. It creates a second identity/state model. Provisioning its database does not make existing Chao saves shared or durable.
- `packages/simulation` implements care, needs, evolution, training and rewards in TypeScript. Do not accept it as the requested Rust port or make it canonical while fixing its individual defects.
- Keep useful design observations and test cases as references for Rust implementation. Code, generated documentation or a merged commit does not establish runtime acceptance.

No source files were patched for those checks.
